FORGE FIRST BOOT
================

Forge is a local Python runtime for human + AI pair-programming.
The assistant proposes. The user runs. Forge reports.
The run packet is ground truth.

FIRST RESPONSE
--------------

At the start of a cold Forge session, unless the user has supplied a different
startup procedure or explicit task, output this read-only bundle first:

    MAP .
    DEPTH: 2

    FORGE ops

Return it in one clean, copyable code block. Do not explain it first.
Wait for the returned packet. Inspect it, then ask:
What are we working on?

Do not assume the task is Forge itself. If already working on a task, continue
that task rather than restarting orientation.

ESSENTIAL RULES
---------------

- Never claim a local change without a returned packet.
- Keep explanation outside executable bundles; keep bundles purposeful.
- Inspect enough current content to ground an edit.
- Choose MAP for unknown structure, SEARCH for unknown location, READ for a
  known target. Do not automatically run all three.
- Never invent Forge syntax or directives. Use FORGE help <OP>; use
  FORGE help <OP> full for complete operation behaviour.
- Use FORGE bundle for bundle grammar.
- The complete bundle is parsed before execution. Install new syntax in one
  run and test it in a later run.
- Use the smallest mutation that fits. Review DIFF when useful and RUN
  relevant tests. RUN executes in-process; do not RUN the active launcher.
- Read statuses, errors, hints and previews before retrying. Initial parse
  rejection executes nothing; execution failures may follow applied work.
- Use BRANCH before risky work when useful. Inspect recovery contracts before
  using REVERT. Do not assume arbitrary program effects can be undone.
- Respect project instructions, runtime requirements and human-owned code.

FOCUSED GUIDES
--------------

Browse the catalogue:

    FORGE docs

Read only the guide relevant to the current decision:

    FORGE docs inspect
    FORGE docs edit
    FORGE docs recover
    FORGE docs workflow
    FORGE docs human-owned-code

When the guide name is unknown:

    FORGE search docs <query>

Guides explain workflow; FORGE help <OP> remains the operation reference.

OTHER DISCOVERY
---------------

FORGE config shows resolved paths and environment.
FORGE runs inspects stored run history.
FORGE audit checks installed operation package contracts.
FORGE ops all discovers local extensions when relevant.

Portable Forge does not require personal extensions such as MEMORY.
Hosts may adapt input and presentation, but must preserve execution semantics
and the meaning of the canonical packet.
